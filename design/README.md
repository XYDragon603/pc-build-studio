# 装机工作台 · UI 第一版

这是用于确认产品布局与交互的静态视觉稿，使用内置 imagegen 生成。图中所有价格、已选配件与兼容性状态都是演示数据，不代表实时行情或当前项目已接通这些功能。

## 设计方向

浅灰白背景、深绿色主要操作、浅绿色选中态；橙色表示待核实，红色表示明确的规格冲突。颜色搭配文字与图标，不用单独颜色表达结论。左侧导航与方案信息，中间八槽配置清单，右侧当前槽位的商品候选，底部显示预算。

选中显卡槽位，右侧展示三种候选状态：登录条件价、显存不符合要求、无法获取价格。所有待核实价格都不计入配置合计；用户可打开来源核实或手动填价。

CPU 展示锁定状态，其他配件保留编辑与锁定入口。自定义配件在列表下方新增。布局用于桌面浏览器，移动端后续单独适配，不按这张图等比缩小。

## 数据与计算约定

- 整机预算：8000 元。
- 七项手动价格：1450 + 799 + 499 + 399 + 399 + 249 + 149 = 3944 元。
- 剩余预算：4056 元；显卡未选择，候选价格不计入合计。
- 兼容性分别呈现接口检查与 BIOS 待确认；缺显卡时，功耗保留未知。
- 零元已有配件与未知价格分开存储。价格未知不可用零元补位。
- 自动重算不能改动已锁定配件；手动价格由用户明确编辑。

## 接下来实现的顺序

1. 按视觉稿制作可交互前端：选择槽位、切换候选、锁定、手动改价、备注、预算合计及本地保存。
2. 补齐加载、无结果、检索失败、过期报价和来源缺失状态，明确区分演示模式与实时模式。
3. 将现有验证模块封装为服务端接口，返回标准报价、证据、状态和原因；密钥仅保存在服务端。
4. 接通实际搜索账号与可用商品数据源，验证延迟、质量和费用，再启用自动入槽。

第一轮前端可以使用明确标记的演示数据完成交互验证。预算重分配、自然语言配单与价格历史待基本工作流稳定后实现。

## 与现有代码的衔接

现有 `src/normalization.mjs` 的 `accepted / review / rejected` 对应可加入、待核实、已过滤。接口应保留 `priceCents`、币种、型号、容量、`observedAt`、来源链接与判定原因。前端将原因转换为简短提示，完整证据放到详情层；不在主流程展示缓存键、API用量实现或JSON字段。

后续新增的配置模型需要独立保存预算、用途、各槽位选择、锁定状态、手动价与备注。报价检索与配置编辑分离：重新查价不会自动覆盖用户手动确认的价格。
