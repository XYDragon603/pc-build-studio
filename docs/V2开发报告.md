# 装机工作台 V2 开发报告

日期：2026-11-25。范围：V2 系统性优化任务（兼容性约束、预算、整机组合优化、场景评分、价格管理、数据质量、三档差异化、界面、回归测试）。

本报告不含中关村在线（ZOL）的价格数据。逐档价格明细与 V1 / V2 并排对比在本机 `配置/V1_V2对比.md` 和 `配置/测试汇总.md`，这两个文件按数据使用约定不提交到公开仓库。

## 1. 结论

- 12 组基线测试共 36 档：V1 有 8 档存在问题（缺档、显卡供电接口警告、超目标预算），V2 剩 3 档，都是低预算档在“非严格预算”下超出本档目标（详见第 9 节）。打开严格预算后，这 3 档改为“无可行方案”，并给出最低可行预算和调整建议。
- 全量扫描 432 套方案（6 种用途 × 18 个预算 × 安静优先开 / 关）：0 套 FAIL，0 套关键项 UNKNOWN，平均每次请求约 0.1 秒。
- 前后端用同一份兼容规则（`src/compat-rules.mjs`），自动配置的搜索阶段就排除 FAIL 组合，而不是事后提示。
- 三档不再是“比例预算内最贵”，而是按场景评分做整机组合优化；评分提升不足 2 分的档位标为“与上一档相同”，不硬凑。
- 价格与规格分开存放：新增价格记录（手动录入、CSV / JSON 导入导出、过期标记、二手 / 无货过滤、两种价格模式）。不抓取、不伪造实时价。
- 测试：后端 129 项、前端 43 项全部通过；界面走查（无头 Chrome）无报错。

## 3. V1 问题与根因

| 现象 | 根因 | V2 处理 |
|---|---|---|
| 高端显卡常报“显卡供电接口”警告（基线 7、12 组） | 后端只认 16pin 原生接口，8pin 显卡一律“未知”；16pin 写法不同时被重复计数 | `parseGpuPower` 统计 6 / 8 / 16pin 数量；16pin 转接按功耗要求 2–4 个 8pin |
| 前端提示与后端结果不一致 | 两边各写一套兼容判断 | 抽出 `compat-rules.mjs`，前端经 Vite 直接导入同一文件 |
| 2K 6000 元配 RTX 3050 + Ryzen 3 3100 | 每档按“比例预算内最贵”逐件分钱，没有整机目标，也不看 CPU / 显卡搭配 | 整机组合优化 + 场景评分 + CPU 拖后腿扣分 + 场景最低要求 |
| 办公 2000 元只返回两档 | 某档凑不齐就被丢弃 | 三档固定返回；无解时说明原因、最低可行预算和建议 |
| 核显兜底替换掉独显方案 | 兜底逻辑不检查完整性 | 只有完整方案才能替换 |
| 内存容量只会往下退 | 回退方向写死 | 上下两个方向都回退 |
| 8GB / 16GB 同芯片显卡共用一个游戏分 | 性能表不区分显存版本 | 性能条目加 `memoryGB`，显存不同不套用并注明 |
| 价格写死在规格里，无法填自己的价格 | 规格与价格同表 | 价格记录单独存放，按价格模式套用 |

## 4. 兼容性规则（五态）

状态：`PASS` 通过；`FAIL` 不兼容（搜索时排除）；`CONDITIONAL` 需满足条件（如开 XMP / EXPO、BIOS 需更新）；`UNKNOWN` 规格缺失待核实；`NOT_APPLICABLE` 不适用（如核显方案的显卡供电）。整机状态取最严重的一项。

| 检查 ID | 内容 | 关键项 |
|---|---|---|
| socket | CPU 与主板插槽 | 是 |
| bios | 代际 × 芯片组：原生支持 / 需更新 BIOS / 不支持（AM4、AM5、LGA1700、LGA1851） | |
| memoryType / memorySlots / memoryCapacity / memorySpeed | 内存代际、条数、最大容量、频率（超出默认频率为 CONDITIONAL） | 代际为关键项 |
| igpuCpu / videoOutput | 核显方案：CPU 有核显、主板有视频输出 | 是 |
| gpuPower / psuWatts / psu12v | 显卡供电接口数量、电源功率余量（≥ 估算满载 × 1.25 且不低于显卡厂商建议）、12V 输出 | 是 |
| coolerSocket / coolerHeight / radiator | 散热器扣具（AM5↔AM4、LGA1851↔LGA1700 等效）、风冷限高、冷排位 | |
| gpuLength / boardFit | 显卡长度、主板板型与机箱 | |
| m2 / pcie / rebar / vrm | M.2 位、x8 显卡插在 PCIe 3.0、ReBAR、供电相数 | |

规格补全（`src/specs-enrich.mjs`）只填缺失字段，不覆盖已有数据：显卡接口 / 尺寸 / 槽宽 / 整卡功耗；电源 8pin / 16pin 数量、ATX 版本、12V 电流、保护、质保；主板芯片组、视频输出、PCIe 代数、M.2 数、供电相数；SSD 颗粒、缓存类型、TBW。

## 5. 整机组合优化引擎

`src/optimizer.mjs`：

1. **候选裁剪**：按场景指标对 CPU、显卡、主板、内存、SSD 做帕累托裁剪（同价位只留更强的），锁定配件直接作为唯一候选。
2. **组合枚举**：CPU × 主板（同插槽、BIOS 非 FAIL）× 显卡 × 内存（同代际）× SSD；电源、散热、机箱由补全器按约束挑最合适的（结果缓存）。
3. **评分**：`scoreBuild` 输出 0–100 总分和七个分项（显卡、CPU、内存、硬盘、品质、噪音、数据可信度），游戏场景再扣 CPU 拖后腿分。
4. **分档**：每档目标 = 预算 × 0.8 / 1.0 / 1.2，最大化 `评分 − λ × 100 × 总价 / 目标`，λ 依次为 0.22 / 0.12 / 0.06（省钱版更看重省钱）。场景最低要求作为软约束：有满足的组合就只在其中选，都不满足时选最好的并写明差在哪里。
5. **严格预算**：`maxOverPercent = 0` 时每档不超过目标；`1–50` 允许超出相应比例。无解时给出原因、最低可行预算和建议（含“锁定配件互相冲突”的说明）。
6. **差异化**：某档比上一档评分提升不到 2 分，就沿用上一档并标 `sameAs`，不为了凑档多花钱；每档 `notes` 写明相对上一档升级了什么、剩余预算怎么用更值。

### 场景评分配置（`src/scoring-profiles.mjs`，版本 2026-11-27）

| 场景 | 显卡 | CPU | 内存 | 硬盘 | 品质 | 噪音 | 可信度 | 说明 |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| 2K 游戏 | 0.50 | 0.18 | 0.07 | 0.05 | 0.10 | 0.02 | 0.08 | 显卡分取 0.7 次方（边际递减） |
| 4K / 光追 | 0.60 | 0.12 | 0.06 | 0.05 | 0.09 | 0.02 | 0.06 | 显卡分线性 |
| 1080p 电竞 | 0.40 | 0.30 | 0.07 | 0.04 | 0.09 | 0.02 | 0.08 | 0.6 次方，CPU 权重高 |
| AI / 机器学习 | 0.52 | 0.08 | 0.14 | 0.07 | 0.10 | 0.01 | 0.08 | 显卡分 75% 看显存（32GB 满分）+ 25% 算力 |
| 剪辑 / 设计 | 0.22 | 0.32 | 0.15 | 0.12 | 0.10 | 0.01 | 0.08 | CPU 看 Blender 多核 |
| 办公学习 | 0 | 0.35 | 0.15 | 0.15 | 0.15 | 0.08 | 0.12 | 不配独显 |

“安静优先”把噪音权重提到 0.12，其余按比例下调。最低要求：2K / 4K / 1080p 游戏指数下限 30 / 45 / 25；AI 显存 ≥ 12GB；剪辑显存 ≥ 8GB；内存按目标预算给下限。

数据来源：游戏指数来自 `data/perf-gaming.json`（TechPowerUp / TechSpot 汇总图，部分换算或估算，条目有标注）；CPU / 显卡算力为 Blender Open Data（CC0）中位数，至少 3 次提交；显存、功耗来自目录规格。分项是同一目录内的相对值，用来比较方案，不代表实际帧数或 AI 吞吐。

## 6. 价格管理

- **存储**：`<数据目录>/prices.json`（桌面版为 `.runtime/prices.json`），与规格分开；原有目录数据和用户方案不需要迁移，旧方案照常打开。新文件不存在时视为空。
- **记录字段**：配件 ID、SKU、价格（分）、币种（CNY）、来源名称、来源链接（HTTPS）、观察日期、状况（全新 / 库存新品 / 二手 / 翻新 / OEM 拆机）、库存、运费、类型（手动 / 已核实 / 参考 / 估算）、可信度、备注。
- **导入导出**：CSV 与 JSON，逐行校验，错误行列出行号和原因、不写入；CSV 导出带 BOM，并对以 `= + - @` 开头的文本加单引号，防止公式注入。
- **价格模式**：参考估算（默认）/ 优先我的价格（有记录用最新一条 + 运费，没有的用参考估算）。默认忽略二手、翻新、拆机和明确无货的记录，可在首页打开“接受二手价”。
- **过期**：目录参考价超过 14 天、用户记录超过 30 天标记过期，界面提示，但仍可使用。
- **界面**：侧栏“价格管理”页（录入、列表、删除、导入、导出）；方案卡显示用了几件“我的价格”、几件已过期；配置页参考价悬停显示依据和采集日期；导出清单增加“价格来源”列和非实时说明。

## 7. 数据质量

运行 `node scripts/data-quality.mjs`，输出 `reports/data-quality.local.md`（只在本机）。当前目录：国内有价条目 2779 件，可信度高 888 / 中 1735 / 低 156；单一来源 1380、同规格价差 3 倍以上 117、上一代产品 389、疑似旧价 22；显存版本不一致 18 处、规格冲突 22 处。

处理原则：疑似旧价、系列起价、同类粗估的条目不进入自动配置；上一代产品在可信度分项扣分；显存版本不同的显卡不共用游戏分。

## 11. 已知限制

- **价格不是实时的**：参考价来自 ZOL 列表页，每周日、周三刷新；没有合法可用的电商实时价接口，京东联盟需要用户自己的密钥。下单前以商城价为准，可在“价格管理”录入实际价格。
- **跨预算评分小幅回落**：相邻预算之间偶有 1 分左右的评分下降（如 4K 6000 元），原因是不同目标下 λ 惩罚和最低要求切换。单元测试在合成目录上验证了档位和预算的单调性；真实目录上跨预算仍可能有这类小回落。
- **规格缺口**：BIOS 支持按“代际 × 芯片组”规则推断，不是逐块主板的 BIOS 版本；供电相数、机箱风道、实测噪音缺数据；CPU 插槽缺 34 件、显卡长度缺 101 件，缺失时判 UNKNOWN 并在可信度分项扣分。
- **性能数据**：TechPowerUp 页面禁止自动抓取，游戏指数依赖汇总图和换算，部分型号为估算；AI 分只看显存和 Blender 算力，不是实际推理吞吐。
- **上一代产品价格**：如 RTX 3090 只有 3 条报价且为上一代，AI 2 万元推荐版会选到它；可信度分项已扣分，建议下单前核实。
- **低预算超目标**：非严格模式下，若目录里最便宜的合格组合仍高于目标，会给出超目标方案并说明；需要硬上限时请打开严格预算。
